# 06: 多产出任务

Parent: [../spec.md](../spec.md)，决策见 [ADR 0005](../../../docs/adr/0005-generation-and-result-cards.md)。

**What to build:**
一次任务产出多个 `TaskAsset` 时，一个资产一张结果卡，自动出现在生成卡右侧。Seedream 图层拆分产出底图加最多 16 个图层，连环组图产出最多 15 帧，各自成为独立结果卡；Midjourney 的 2×2 网格仍是一张。占位卡在任务成功后变成第一个资产的结果卡，其余资产依次新建并按网格排布。同一个终态被重复送达（SSE 与打开工程时的补齐各来一次）时不会重复建卡。

**Blocked by:** 01: 图片结果卡主线（tracer bullet）

**Status:** done

- [x] 任务成功且资产不止一个时，占位卡成为第一个资产的结果卡，其余资产各新建一张，顺序：底图在前，图层按 `z_index`，分镜帧按 `asset_index`
- [x] 额外结果卡的 id 由 `taskId` 与资产序号派生；把同一个终态送两次（或先 SSE 再补齐），最终卡片列表与只送一次完全一致，没有重复
- [x] 额外结果卡都带上 `taskId`、来源字段和各自的资产，参数快照与第一张一致；图片结果卡各自分配 `@图N`
- [x] 多张结果卡按网格排布，第一个落点仍是第一个空位；每张卡的高度按各自图片宽高比确定，不与任何已有卡重叠，也不挪动已有卡片
- [x] Midjourney 任务只有一张 2×2 网格图，只产生一张结果卡
- [x] 新流程的生成卡不再出现「展开图层」「展开分镜」按钮（旧卡上的旧按钮留到 10 再移除）
- [x] 单元测试覆盖：图层拆分 1 底图 + 16 层共 17 张卡、连环组图 15 帧、Midjourney 一张、终态重复送达的幂等、网格落点不重叠、编号连续
- [x] 开发服务器走查：用 mock 服务商跑图层拆分，看到 17 张结果卡整齐排开，框选后可批量删除

## Comments

- 2026-09-29 实现完成。`applyTaskToCards` 只更新按 `taskId` 找到的占位卡；占位卡第一次成功时保留排序后的第一个资产（底图 → 图层按 `z_index` → 分镜按 `asset_index`），其余资产各建一张结果卡，id 为 `result-<taskId>-<asset_index>`，按 `ceil(√n)` 列网格从占位卡起逐列取第一个空位（`layout.ts` 新增 `firstFreeSlotBelow`）。到终态的结果卡不再接收快照，所以重复送达不改变任何东西，用户删掉的额外卡也不会被补回。图层卡按 `bounding_box.absolute` 的宽高比估高（方舟文档：图层按边界框裁切）；底图与分镜仍按请求比例。只拆图片任务：视频任务附带的尾帧不单独成卡。新模型卡不再有「展开」按钮和图层切换条，旧卡保留到 10。
- 走查（独立的无密钥后端，fake 适配器）：fake 的图层拆分只返回底图 + 2 层，看到 3 张结果卡（@图1–3，2 列网格，连线到生成卡），框选后 Delete 一次删掉 3 张。17 张的情况只在单元测试中验证。fake 资产都是 1×1 PNG，加载后卡变成正方形，与 16:9 的估算不符，所以走查中底图卡与下方卡有重叠；真实出图的尺寸与请求一致时不会出现。实际出图比例偏离请求时（任何服务商）仍可能重叠，这是 01 起就接受的「未知高度用估计值」的代价。
