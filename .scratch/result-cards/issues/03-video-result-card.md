# 03: 视频结果卡

Parent: [../spec.md](../spec.md)，决策见 [ADR 0005](../../../docs/adr/0005-generation-and-result-cards.md)。

**What to build:**
视频生成卡走与图片同样的流程：点「生成」后右侧出现一张视频结果卡，带进度，成功后内嵌循环播放，失败保留错误；一张视频生成卡可以产出很多张视频结果卡。视频结果卡暂时没有输出端口，因为目前没有任何下游能接收视频。

**Blocked by:** 02: 生成卡卡面与结果卡参数快照

**Status:** done

- [x] 新建的视频卡是生成卡，走占位结果卡流程；生成卡的卡面规则与图片一致（无预览区、按钮永远「生成」、N 个生成中、提交前失败留在生成卡）
- [x] 视频结果卡：成功后显示内嵌循环播放器，运行中显示进度，失败、取消、过期显示错误；卡片按视频宽高比确定预览高度，落点布局据此避免重叠
- [x] 视频结果卡的参数快照包含模式、分辨率、时长、比例、是否有声、seed 以及所用参考图的摘要；在检查器里只读显示
- [x] 视频结果卡没有输出端口，也没有输入端口
- [x] 视频生成卡仍可通过现有方式引用图片（旧图片卡或后续的图片结果卡），不因本票破坏
- [x] 单元测试覆盖：视频任务的占位卡创建、终态回填、快照内容；引用带图片的视频任务所产生的结果卡快照
- [x] 开发服务器走查：用 mock 服务商连点两次视频生成，得到两张各自能播放的视频结果卡

## Comments

- 2026-09-29 实现完成。新建视频卡为生成卡（无 `@图N`，按自身数量编号），走 `addPendingResult` / `applyTaskToCards` 同一条链路；提交时按类型选 `compileCardVideoPayload`。快照参数为模式、清晰度、时长、比例、是否有声，seed 取 `seed`，参考图摘要存 `snapshot.references`。模式对比例和参考图角色的改写抽成 `videoCompiler.ts` 的 `sentVideoSettings`，编译器和快照共用，所以快照记录的是实际发出的值（首尾帧 → `adaptive` 比例、按顺序定首尾帧；纯文字不带参考图）。`RunsBadge` 移到 `CardShell` 供两种卡共用。
- 结果卡的开发用 JSON 对视频仍显示原始快照：编译请求需要解析所引用卡的资产，而这些卡可能已被删除。
- 走查用的是独立的无密钥后端（单独的 db 和工程目录），因为本机共享后端的 Ark 与 MiniMax 都配置了真实密钥。
- 已知：占位卡按请求的比例估高（首尾帧 / 自适应时按 16:9）；mock 视频是 4:3，加载后结果卡会变高，可能与下方结果卡重叠（与 01 相同，不挪动已有卡）。
