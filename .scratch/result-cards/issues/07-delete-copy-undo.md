# 07: 删除、复制、撤销

Parent: [../spec.md](../spec.md)，决策见 [ADR 0005](../../../docs/adr/0005-generation-and-result-cards.md)。

**What to build:**
让结果卡在日常编辑操作里表现正确。删除生成卡时，它的结果卡保留并变成没有来源的独立卡；删除结果卡时，指向它的连线一并清除；删除一张仍在运行的占位卡只是删卡，任务照跑。复制沿用「连线只在两端都被复制时才保留并重映射」：复制生成卡不带走它的结果卡，单独复制结果卡得到独立结果卡，占位卡不可复制。撤销只回退用户的手动编辑，任务产生的结果卡永远不会被撤销删掉，用户主动删除结果卡仍然可以撤销。

**Blocked by:** 01: 图片结果卡主线（tracer bullet）

**Status:** done

- [x] 删除生成卡：它的结果卡全部保留，来源字段清空，变成独立结果卡，连线消失
- [x] 删除结果卡：指向它的提示词来源和参考图一并清除；删除后其他结果卡与生成卡不受影响
- [x] 删除仍在排队或运行的占位卡：只删卡，之后到达的该任务事件被忽略，不报错
- [x] 复制生成卡：默认不复制其结果卡；生成卡与结果卡一起被选中时，副本之间的来源关系被重映射；新卡的 id 与 `@图N` 都是新的
- [x] 单独复制一张结果卡：得到没有来源的独立结果卡，不带 `taskId`；处于排队或运行中的占位卡不可复制
- [x] 撤销：恢复快照后，把快照之后由任务产生的结果卡并回来（含仍在运行的占位卡及其 `taskId`）；用户主动删除结果卡可以撤销，撤销后带着原来的 `taskId` 回来
- [x] 撤销 / 重做不会把生成卡回退成旧任务状态，也不会让任务产生的结果卡消失
- [x] 单元测试（沿用 `cardFactory.test.ts` 的复制用例与撤销合并的现有测试）覆盖：以上每条的输入与期望输出，包括「复制的占位卡被拒绝」「撤销后任务卡仍在」
- [x] 开发服务器走查：生成三张结果卡，删生成卡，结果卡仍在；再撤销，生成卡回来并恢复来源连线

## Comments

- 2026-09-29 实现完成。`removeCards` 在删生成卡时把其结果卡的 `sourceId` 清空（占位卡保留 `taskId`，任务照跑）。`mergeTaskState` 默认保留快照之后任务产生的结果卡；重做时只丢掉被重做的那次编辑删掉的卡（历史的 redo 栈同时记下撤销恢复的快照来算出这一集合），因此撤销后任务新产出的结果卡在重做时不会消失；来源已不在的保留卡变成独立卡。撤销恢复回来的仍在排队/运行的占位卡会立即拉一次任务状态（`restoredAwaitingTask`），补上删除期间被忽略的 SSE 事件。复制只拒绝排队/运行中的结果卡，并提示「生成中的结果卡不能复制」；失败的结果卡仍可复制（得到带错误、无 `taskId` 的独立卡）。
- 走查（无密钥后端，fake 适配器）：生成 3 张结果卡，删生成卡，3 张结果卡留下、连线消失、落盘的 `sourceId` 为空；Ctrl+Z 后生成卡回来，3 条连线恢复。fake 任务不到 1 秒就完成，来不及在运行中删占位卡，这条只在单元测试中验证。
