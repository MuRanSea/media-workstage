# 08: 旧工程迁移（核心）

Parent: [../spec.md](../spec.md)，决策见 [ADR 0005](../../../docs/adr/0005-generation-and-result-cards.md)。

**What to build:**
打开旧工程时，自动把没有角色字段的旧卡片迁移成新模型，创作者什么都不用做。每张带结果或进行中任务的旧图片 / 视频卡拆成「生成卡 + 结果卡 + 连线」；旧文本卡的输出变成一张文本结果卡；从未运行过的旧卡直接成为生成卡。旧图片卡的 `@图N` 编号让给它迁移出来的结果卡，旧的参考图和提示词连线重指向结果卡，所以旧视频提示词里的 `@图3` 仍指向原来那张图。迁移是纯函数，重复打开结果一致，下次自动保存即落盘。本票只覆盖单资产的常规情况，多资产、展开产物和失败卡放在 09。

**Blocked by:** 05: 结果卡连线复用

**Status:** done

- [x] 判定：卡片缺少角色字段即为旧卡片；已有角色字段的卡片原样保留
- [x] 有结果的旧图片 / 视频卡：原卡保留原 id、位置、标题和参数并成为生成卡，清空任务与结果字段、状态归零；迁出一张结果卡，id 由原卡 id 派生，落点按 01 的布局规则（第一个空位，不挪动已有卡）
- [x] 进行中（排队 / 运行，且有 `taskId`）的旧卡：迁出一张占位结果卡并沿用该 `taskId`，之后的 SSE 与补齐能继续更新它；没有 `taskId` 的进行中旧卡（提交阶段中断）归零为空闲，不迁出结果卡
- [x] 有非空输出的旧文本卡：原卡成为生成卡，输出成为一张文本结果卡；输出为空的旧文本卡直接成为生成卡
- [x] 从未运行的旧卡直接成为生成卡，只补上角色字段
- [x] 编号：旧图片卡的 `tagIndex` 让给迁出的图片结果卡，生成卡不再持有编号，旧视频提示词里的 `@图N` 仍指向同一张图
- [x] 连线：旧 `references` 里的卡片 id、旧 `promptSourceId` 重指向迁出的结果卡，参考图不再使用旧的地址快照；所指旧卡没有任何结果时，该连线直接清除
- [x] 重复执行：把迁移后的结果再迁移一次，或把同一份旧数据迁移两次，输出完全一致，没有重复卡
- [x] 迁移不改变任何已有卡片的位置；迁出的结果卡落在空位上
- [x] 单元测试（沿用 `projectDoc.test.ts` 的写法）覆盖：上面每一类旧卡、编号继承、连线重指向、连线清除、幂等
- [x] 用一个真实的旧工程文件（复制一份现有 `projects/` 下的工程）打开，看到旧结果以结果卡的形式在原卡右侧，原有连线仍在，视频卡能再次生成

## Answer

提交 `4e1817c`（后续整理见 `8f861cf`）。`web/src/engine/migration.ts` 的 `migrateLegacyCards` 在 `normalizeCards` 里调用：没有角色的旧卡原位变成生成卡（保留 id、位置、标题、参数），输出、进行中任务迁成结果卡，结果卡 id 由原卡 id 派生（`<id>-result` / `<id>-run`），按「第一个空位」落位。`@图N` 让给显示原图的结果卡；`references` / `promptSourceId` 重指向结果卡，所指旧卡没有结果时清除，地址快照去掉。迁移是纯函数，重复执行结果不变。测试在 `migration.test.ts`。

决定：旧卡「仍在运行」时，指向它的连线重指向占位结果卡（结果会落在那里，和旧行为一致），不清除；同一 `taskId` 被两张旧副本共享时只有一张拿到占位卡。

走查：用打包程序打开复制出来的旧工程「测试」（14 → 29 张卡）和「视频测试」，结果卡在原卡右侧，连线都在；旧视频卡再次生成时参考图仍是原图（`@图1` → `tL/base.png`）。
