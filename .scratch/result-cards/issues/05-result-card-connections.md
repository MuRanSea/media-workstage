# 05: 结果卡连线复用

Parent: [../spec.md](../spec.md)，决策见 [ADR 0005](../../../docs/adr/0005-generation-and-result-cards.md)。

**What to build:**
让结果卡真正成为可复用的素材。只有结果卡有输出端口：图片结果卡可以作为视频生成卡的参考图，文本结果卡可以作为图片或视频生成卡的提示词来源；下游固定指向某一张具体的结果卡，之后重新生成不会改变已连好的下游。参考图直接从图片结果卡读取资产，不再使用连线时保存的地址快照，所以图片重新生成之后，视频仍然引用原来那张图，顺带修掉了「引用旧图」的问题。所连文本结果卡为空或仍在运行时，生成给出明确提示，不静默使用旧提示词。

**Blocked by:** 03: 视频结果卡; 04: 文本结果卡

**Status:** done

- [x] 端口规则：图片结果卡、文本结果卡有输出端口；生成卡、视频结果卡没有输出端口；结果卡没有输入端口；图片和视频生成卡保留输入端口
- [x] 连线规则：文本结果卡 → 图片 / 视频生成卡，成为提示词来源；图片结果卡 → 视频生成卡，成为参考图；图片结果卡 → 图片生成卡、文本卡之间的连线仍被拒绝并给出原因；重复连接被拒绝
- [x] 视频生成卡的参考图从所指的图片结果卡读取资产；同一张图片生成卡后来又产出了新图片，视频卡仍引用原来那张
- [x] 参考图上保存的地址快照字段不再参与解析（无需立即删除字段，删除放在 10）
- [x] 连到视频卡的图片结果卡所属的 `@图N` 出现在提示词和参考池里，行为与现在一致
- [x] 生成时所连文本结果卡内容为空或仍在运行，给出明确提示并且不发出任务；有内容时以该结果卡的文本作为提示词
- [x] 删除被连线的结果卡时，指向它的提示词来源和参考图一并清除（沿用现有清理逻辑，对结果卡同样有效）
- [x] 单元测试（沿用 `connections.test.ts`、`videoCompiler.test.ts`）覆盖：各种源 / 目标组合的允许与拒绝、参考图来自结果卡、重新生成后仍引用原图、提示词来源为空 / 运行中 / 有内容
- [x] 开发服务器走查：图片生成两次，把第一张连到视频卡；再生成第三张图，视频卡的引用仍是第一张

## Comments

- 2026-09-29 实现完成。端口与连线规则在 01–04 中已基本到位，本票补齐并测试了所有源 / 目标组合。`attachImageToVideo` 不再写入 `url` 快照；`resolveReferenceAsset` 只从所指卡片读取资产，`ReferenceItem.url` / `localPath` 标记为弃用（删除留给 10）。`withEffectivePrompt` 在所连文本卡排队或运行中时报「还在生成中」。删除清理抽成 `connections.ts` 的纯函数 `removeCards`，`SpatialCanvas` 调用它。
- 行为变化：没有角色字段的旧图片卡重新生成后，连着它的视频卡会改用新图（以前用连线时快照的旧地址）；这是 spec 所说的「引用旧图」问题的修复。所指卡已不在画布上的参考图现在会报错，而不是退回快照地址。
- 走查（独立的无密钥后端）：图片生成两次，把 #1 连到视频生成卡（提示词自动加 `@图1`，参考池显示 @图1），再生成第三张；视频卡的请求 JSON 仍引用第一个任务的资产，随后视频任务提交成功。提示词来源为空或运行中的提示只在单元测试中验证，界面未走查。
