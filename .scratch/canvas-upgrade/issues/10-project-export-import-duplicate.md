# 10: 工程导入导出与复制

Parent: [../spec.md](../spec.md)

**Status:** done

**What to build:**
工程切换器里加三项：「导出」把整个工程文件夹（`project.json` 和 `assets/`）打成 zip；「导入」选一个 zip 生成新工程，工程 ID 重新生成，名称重名时自动加后缀；「复制工程」在工程目录里复制出一份新工程。模板不设独立概念，复制工程即为模板用法。导入时校验 zip 内路径，不允许穿出工程目录。桌面模式和浏览器模式都要能用。

**Blocked by:** 无

- [x] 导出的 zip 解压后与工程文件夹内容一致，卡片媒体的相对路径仍然有效
- [x] 导入 zip 后得到新 ID 的新工程，卡片和媒体都能正常显示；原工程不受影响
- [x] 重名时自动改名；坏 zip 或不是工程的 zip 给出明确错误，不留下半成品文件夹
- [x] zip 里带 `../` 的路径被拒绝
- [x] 复制工程得到独立的新工程，修改任一份不影响另一份；任务产出仍写入各自工程
- [x] 后端测试覆盖：往返（导出再导入）、重名、坏 zip、路径穿越；工程目录里没有残留

## Comments

- 2026-10-10 实现完成。
  - 后端 `internal/project/transfer.go`：`Export`（把工程文件夹打成 zip，跳过 `.tmp` 残留）、`ExportToFolder`（写到 `<工程目录>/.exports/<名称>-<时间>.zip`；以点开头的文件夹不会被当作工程读取）、`Import`、`Duplicate`。导入和复制都先写进 `.staging-*` 临时文件夹，成功后再改名到位；任何失败都删除临时文件夹，不留半成品。
  - 导入校验：zip 内必须有 `project.json`，放在根目录，或在唯一一层顶级文件夹里（手动压缩的工程文件夹）。拒绝 `..`、绝对路径、带盘符或反斜杠穿越的条目和符号链接；解压总量上限 20 GiB，文件数上限 20 万；实际内容超过声明大小即拒绝。
  - 新工程：重新生成 ID，revision 归 1，名称重名时加 " (2)"、" (3)"…；复制的名称为"<原名> 副本"。
  - 取舍：原工程里仍在排队或运行的结果卡，在副本里标为失败（"复制工程时该任务尚未完成，结果只会出现在原工程中"）并去掉 `taskId`。任务产物只会下载到原工程的文件夹，副本永远等不到它们。已完成的卡保持原样。
  - 接口：`GET /api/projects/:id/export`（下载，`filename*=UTF-8''…` 支持中文文件名）、`POST /api/projects/:id/export`（导出到文件夹，并用 `explorer /select` 打开）、`POST /api/projects/import`（multipart 字段 `file`，坏文件返回 400）、`POST /api/projects/:id/duplicate`。
  - 前端：工程列表顶部"导入工程"；每个工程的 ⋯ 菜单和画布里的工程切换菜单增加"复制工程""导出为 zip"。导出在浏览器模式下走下载；在桌面模式（`/api/desktop` 的 `enabled`）下改为导出到文件夹并在资源管理器中选中，因为桌面窗口没有下载管理。
- 测试：Go `transfer_test.go`（往返、重名、手动压缩的文件夹、7 种坏包含路径穿越且不留残留、未完成任务的处理、复制互不影响且任务写入副本、导出到文件夹），`projects_test.go` 新增接口层导出→导入→复制。前端 343 条全部通过，`tsc` 通过。
