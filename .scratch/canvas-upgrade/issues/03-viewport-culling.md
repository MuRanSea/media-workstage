# 03: 视口裁剪与渲染性能

Parent: [../spec.md](../spec.md)

**Status:** done

**What to build:**
目标是一个工程 200～300 张卡仍然流畅。视口外（加余量）的卡片不渲染，改成同尺寸占位；被选中的卡、正在拖动的卡、有运行中任务的卡保持挂载；连线只画与可见卡相关的部分。同时给卡片组件加 `React.memo`，拖动时只更新被移动的卡；槽位偏移的 DOM 测量不要在每次渲染都执行；框选 mousemove 不再每次新建整张 Set。任务进度走 SSE 写入 state，不依赖 DOM，裁剪不能影响任务同步。

**Blocked by:** 01: 实测卡高

- [x] 视口外的卡片不挂载 DOM，进入视口（含余量）时自然出现，不闪烁
- [x] 选中的、拖动中的、有运行中任务的卡始终挂载
- [x] 被裁剪的卡上任务完成时，结果仍然更新进 state 并保存；回到视口时看到的是最新结果
- [x] 平移和缩放时，视口内未变化的卡不重渲染（`React.memo` 生效）
- [x] 连线只计算和渲染可见部分
- [x] 单元测试覆盖：可见性判定（含余量、缩放）；必须挂载的集合
- [x] 开发服务器走查：造 300 张卡，平移、缩放、拖动、框选都不明显卡顿；记录改动前后的帧率或渲染耗时

## Comments

- 2026-10-09 实现完成。
  - `engine/culling.ts`：`visibleWorldRect`（视口 + 每边 400 屏幕像素余量换算到世界坐标）、`cardsToRender`（与可见区相交的卡，加上必须挂载的卡，保持原顺序）、`lineMayCross`（连线按端点包围盒加曲线外凸量判断）、`sameIds`。
  - 必须挂载：选中的卡（拖动的卡总是选中的）、正在拖出连线的源卡、`queued` / `running` 的卡。
  - 视口外的卡**直接不挂载，没有做同尺寸占位**：它们在屏幕外，占位不可见，只会多出 DOM。
  - 新增 `components/CanvasCard.tsx`：`React.memo` 卡片组件。画布把处理函数放进一个生命周期内不变的 `CardActions` 对象（内部转调最新函数），依赖其他卡的值（提示词来源标题/文本、运行数、忙碌动作）都以原始值传入，所以平移、缩放、拖动别的卡都不会让它重渲染。`availableImageCards` 在内容（卡片对象）不变时保持同一数组。
  - 槽位偏移的 DOM 测量从"每次渲染"改为只在卡片变化或挂载集合变化时执行；裁剪掉的卡保留上次的槽位，已删除的卡清掉。
  - 框选移动时，选择集合成员没变就保留原 Set，不触发重渲染。
  - 高度表随之调整：卡片卸载（被裁剪）时**保留**最后一次测得的高度，改由 `CanvasPage` 在卡片列表变化时 `retain` 掉已删除的卡（工单 01 原写"卸载即清除"，此处有意改变）。
- 测试：新增 `culling.test.ts` 10 条、`cardMetrics.test.ts` 补 `retain`；前端 300 条全部通过，`tsc` 通过。
- 走查（临时工程，300 张图片生成卡排成 20×15 网格，已删除；开发构建，单次滚轮事件从派发到 React 提交加强制布局的耗时）：
  - 改动前：挂载 300 张，平移中位数 50.1ms / p90 89.5ms，缩放中位数 50.3ms / p90 55.5ms。
  - 改动后：挂载 30 张，平移中位数 5.0ms / p90 11.4ms，缩放中位数 5.5ms / p90 11.6ms。
  - 沿网格平移，卡片随视口进出，挂载 42 张、屏幕内 15 张，标题与位置正确；控制台无新错误。
- 未做：缩小到能看到全部卡片时（适应视图），仍会挂载全部 300 张。远景下的简化渲染（React Flow 的 Contextual Zoom）留给以后。
