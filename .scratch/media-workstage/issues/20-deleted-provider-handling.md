# 20: 服务商不存在时的收尾处理

**What to build:**
卡片和任务只保存服务商 ID。自定义服务商被删除，或把工程拷到另一台没有这个服务商的机器上打开时，引用它的卡片与任务要有明确、可恢复的表现，而不是静默失败或自动换到别的服务商。

**Blocked by:** 19-custom-openai-compatible-providers

**Status:** resolved

- [x] 删除自定义服务商时，该服务商下 `queued` / `running` 的任务立即标记为失败，错误码 `ProviderDeleted`，错误信息"服务商已删除"，并通过 SSE 推送；同时从适配器注册表移除（轮询器找不到适配器时本来就会让任务失败，这里是让删除当下就给出准确原因）
- [x] 卡片引用的服务商 ID 不在当前服务商列表里时：保留卡片上原有的服务商 ID 与模型，不自动迁移到提供同名模型的其他服务商
- [x] 这类卡片的服务商选择器显示 `<服务商 ID>（已不存在）`，生成按钮不可用，并提示"服务商已不存在，请重新选择"；用户在选择器里选了新服务商后恢复正常
- [x] 上述判断同时覆盖"服务商被删除"与"工程在另一台机器打开"两种来源
- [x] 单测覆盖：缺失服务商的选项构建（`channelModels.ts`）与删除时的任务失败

说明：目前没有任务历史界面，"已删除服务商"的展示只落在卡片上。

## Answer

后端：`TaskPoller.FailProviderTasks` 把某服务商下 `queued` / `running` 的任务标为失败并经 SSE 推送 `task.failed`；`DELETE /api/providers/:id` 先移除适配器再调用它（错误码 `ProviderDeleted`，信息"服务商已删除"），响应带 `failed_tasks`。

前端：`isProviderMissing`（配置已加载且不再列出该 ID 才算缺失，删除与换机器打开同一判断）。图片 / 视频 / 文本卡的生成按钮禁用并显示"服务商已不存在，请重新选择"；属性面板的服务商选择器显示 `<ID>（已不存在）`；画布层（含右键菜单"生成"）同样拦截并提示。卡片保留原服务商 ID 与模型，重新选择后恢复。

验证：新增 Go 测试（删除时 2 个待处理任务失败，已完成任务与其他服务商任务不变）和 3 个前端单测，Go 全部与前端 80 个单测通过。打包程序走查：图片卡选自定义服务商后在设置页删除它，卡片按钮变为提示、属性面板显示 `custom-c5fe23（已不存在）`，右键"生成"只弹提示不建任务，改选火山方舟后恢复 Seedream 并可生成。

备注：新测试第一次与其余测试一起跑时失败过一次且无断言输出，之后 90 多次重复运行未复现，疑为 Windows 下临时数据库文件清理时的文件占用。
