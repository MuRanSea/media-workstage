# 20: 服务商不存在时的收尾处理

**What to build:**
卡片和任务只保存服务商 ID。自定义服务商被删除，或把工程拷到另一台没有这个服务商的机器上打开时，引用它的卡片与任务要有明确、可恢复的表现，而不是静默失败或自动换到别的服务商。

**Blocked by:** 19-custom-openai-compatible-providers

**Status:** ready-for-agent

- [ ] 删除自定义服务商时，该服务商下 `queued` / `running` 的任务立即标记为失败，错误码 `ProviderDeleted`，错误信息"服务商已删除"，并通过 SSE 推送；同时从适配器注册表移除（轮询器找不到适配器时本来就会让任务失败，这里是让删除当下就给出准确原因）
- [ ] 卡片引用的服务商 ID 不在当前服务商列表里时：保留卡片上原有的服务商 ID 与模型，不自动迁移到提供同名模型的其他服务商
- [ ] 这类卡片的服务商选择器显示 `<服务商 ID>（已不存在）`，生成按钮不可用，并提示"服务商已不存在，请重新选择"；用户在选择器里选了新服务商后恢复正常
- [ ] 上述判断同时覆盖"服务商被删除"与"工程在另一台机器打开"两种来源
- [ ] 单测覆盖：缺失服务商的选项构建（`channelModels.ts`）与删除时的任务失败

说明：目前没有任务历史界面，"已删除服务商"的展示只落在卡片上。
