# ADR 0009: 分区是画布上的区域，不是卡片

## 上下文 (Context)
画布上的卡片越来越多（目标是 200～300 张仍然流畅），用户需要把一组相关的卡片圈在一起、起个名字、整体移动、必要时折叠。调研的几个开源画布都有这类能力：huobao-canvas 把分组做成一种节点，ComfyUI 做成可发布的子图，Figma 系的产品叫 Section。

本项目的画布不是通用节点图：连线存在目标卡的字段里（`promptSourceId`、`references[]`、`sourceId`，见 ADR 0005），卡片只有生成卡和结果卡两种角色。分组如果做成第三种卡片，就要给它让出端口、连线校验、复制、撤销、任务同步里的每一条分支。

## 决策 (Decision)
- **分区（Section）不是卡片**。它没有端口，不能连线，不属于 `MediaCardNode`，不参与 `@图N` 编号。工程文档 `project.json` 在 `cards` 之外新增 `sections[]`，每项是 id、标题、位置、尺寸和折叠状态。
- **归属靠几何包含判定**，不存成员列表：卡片落进区域就属于它，拖出去就不属于。移动分区时，位置落在区域内的卡片一起移动。
- **折叠只是展示层**：折叠后分区缩成标题条，里面的卡片和它们的连线暂时隐藏，卡片数据不变，连线数据结构不变。
- **分区的标题就是唯一的注释手段**，不引入便签卡。
- 分区的创建、移动、缩放、折叠、删除、复制都进入撤销历史。删除分区只删区域本身，里面的卡片保留。

## 考虑过的方案 (Considered Options)
- **分区做成一种卡片**：复用卡片的选择、拖动、复制、撤销，但要在连线校验、卡片工厂、任务同步里给它排除一堆例外；`CardShell` 的标题栏拖动、端口、检查器面板也都要分叉。
- **只做临时多选，不做持久分区**：不改文档结构，但无法命名，也无法折叠，大画布依然没法组织。
- **显式存成员列表**：折叠时不用算几何，但卡片拖进拖出要同步维护列表，撤销、复制、迁移多一条容易出错的路径。

## 结果与影响 (Consequences)
- **正面**：连线数据结构和 ADR 0005 的角色模型都不动；分区的逻辑集中在引擎里，不污染卡片。
- **权衡**：`project.json` 增加了字段，旧版本打开新工程会忽略 `sections[]`（卡片仍在，分区丢失）；归属按几何判定，两个分区重叠时需要一个确定的优先规则（取面积较小、较晚创建的那个）。
- **已知限制**：折叠后隐藏的卡片仍参与保存和任务同步，但看不到进度；运行中的任务完成时用 toast 提醒。
