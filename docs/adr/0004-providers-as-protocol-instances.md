# ADR 0004: 服务商是接入协议的实例

## 上下文 (Context)
服务商原本是写死的 7 个"渠道"：后端 `channelSpecs`、前端 `ChannelId` 联合类型、`system_configs` 的 `<id>_*` 键、适配器注册表都以固定 ID 为键，"是不是 `ark`"同时代表"用哪个适配器"和"套用哪套模型规则"。用户需要接入任意 OpenAI 兼容中转站，并且同一类型可以开多个（例如两个中转站都提供 `gpt-image-2`），靠改名区分。

## 决策 (Decision)
- **服务商（Provider）是某个接入协议（Protocol）的实例**：稳定 ID、可改的唯一显示名、Base URL、密钥、绑定模型，协议在创建时选定且不可更改。适配器按协议实现、按服务商实例化；所有原本按服务商 ID 分支的逻辑（Seedream 规则、可运行卡片类型、文本生成端点）改为按协议分支。
- **内置服务商是预置实例**：沿用 `ark`、`minimax`、`openai` 等原有 ID，无需迁移卡片、任务或 `system_configs`；可改名、可清空密钥，不可删除；环境变量回退与 Ark / MiniMax 的无密钥 mock 仍只挂在预置实例上。
- **第一版只开放"OpenAI 兼容"协议的新增入口**，自定义服务商 ID 形如 `custom-xxxxxx`。预置的 OpenAI 服务商即该协议的实例，因此自定义服务商同时获得文本（`/chat/completions`）和生图（`/images/generations`）。
- **服务商配置是应用级的**（本机 `system_configs`），不写入工程文件夹；工程只存服务商 ID，找不到时卡片提示重新选择，不自动迁移到同名模型的其他服务商。
- **模型能力定义跟着协议走，而不是模型 ID**：Seedream 专属规则只在 Ark 原生协议上生效，同一模型经中转站进来时按通用参数处理，因为协议才决定哪些参数能真正传到上游。

## 考虑过的方案 (Considered Options)
- **内置服务商保持单例，只让 OpenAI 兼容可多开**：改动小，但会留下"内置"和"自定义"两套服务商概念，日后想开第二个 Ark 账号时要重新建模。选择统一模型、仅在入口处收窄，放开其他协议只需开放入口。
- **能力定义按模型 ID 共享**：中转站通常只转发通用参数，按模型 ID 套用专属参数（如图层拆分）会在上游静默失效。
