# ADR 0006: 结果动作产出结果卡（不引入派生卡）

## 上下文 (Context)
Midjourney 的四宫格带一排后续按钮（U1–U4 放大、V1–V4 变体、重绘等），Describe 则把一张图反推成提示词。`feat/mj-full` 分支在旧的「结果写回原卡」模型上实现了这些功能：点击按钮新建一张「派生卡」（`derivedFrom` 记录来源卡、来源任务和动作），派生卡本身是一张可以反复点「生成」的卡。

这个分支开发期间，`master` 已经改成「生成卡 + 结果卡」（ADR 0005）：生成卡只保存设置，每次运行的产出各成一张结果卡。两套机制都在回答同一个问题——「产出如何变成画布上的新卡」——不能同时存在。

## 决策 (Decision)
- **结果动作和 Describe 直接产出结果卡**，不再有派生卡。结果卡的 `sourceId` 可以指向另一张结果卡（动作所作用的那张），`origin` 记录操作（`action` / `describe`）、显示名（「U2」「重绘」「反推」）和动作 ID。来源连线沿用生成卡 → 结果卡的灰线，中间标注操作名。
- **按钮长在结果卡上**：任务成功时带回的 `result_actions` 存在结果卡上；点一次就提交一个 `action` 任务，后端接受后出现一张新的占位结果卡，此后和普通生成一样由 SSE 更新。想再放大一次就再点一次按钮，不需要「重新生成」派生卡。
- **Describe 产出文本结果卡**：图片结果卡或上传图片的右键菜单「Midjourney 反推提示词」，结果是一张异步到达的文本结果卡，可以连到生成卡当提示词。
- MJ 生成卡新增速度（`accountFilter.modes`）、参考图（最多 5 张，连线接入）与 Blend；这些是生成卡的设置，结果卡快照里记录。
- `feat/mj-full` 的「视频卡连视频卡作参考视频」被 `master` 的视频结果卡引用取代；手填素材库 ID（`assetRefs`，含音频）是 `master` 没有的能力，保留在 Seedance 视频生成卡上。
- 用 `feat/mj-full` 保存过的工程在打开时迁移：生成卡上的按钮挪到它的结果卡，`videoReferences` 转成指向视频结果卡的参考。

## 考虑过的方案 (Considered Options)
- **保留派生卡，作为第三种角色**：派生卡既像生成卡（能运行）又像结果卡（有输出、能被引用），渲染、复制、删除、撤销、迁移都要多一条分支；而它唯一的「设置」就是来源任务和动作 ID，没有需要反复编辑的参数。
- **动作结果挂回原生成卡**：结果卡的来源统一是生成卡，连线更简单；但看不出 U2 放大的是哪一张四宫格，同一生成卡的多次运行各有自己的按钮时会混在一起。

## 结果与影响 (Consequences)
- **正面**：画布上只有生成卡与结果卡两种角色；动作结果可被下游稳定引用，也能继续带自己的按钮（放大后的图还有 Vary / Zoom 等）。
- **权衡**：`sourceId` 不再总是生成卡，依赖「来源是生成卡」的逻辑（如「N 个生成中」计数）只对生成卡有意义；复制出的结果卡没有任务，按钮随之去掉。
- **已知限制**：Describe 依赖一个已配置、绑定了图片模型的 Midjourney 服务商；动作任务必须由原服务商执行，服务商被删后按钮无法使用。
