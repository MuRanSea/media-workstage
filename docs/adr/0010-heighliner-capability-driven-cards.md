# ADR 0010: Heighliner 卡片的参数由能力描述驱动

## 上下文 (Context)
新增的 Heighliner 平台协议（网关的 `/media/v1` 媒体平台协议加上 `/v1/chat/completions` 文本入口）只用一把虚拟密钥，就能跑 Seedream、Seedance、可灵、MiniMax-H3 和混元/Tripo 3D。网关的模型目录 `GET /media/v1/models` 给出每个模型的**能力描述**：`parameters`（类型、枚举、范围、默认值）、`references`（角色、媒体类型、数量、是否接受素材库 ID）和 `provider_options_schema`。网关的校验很严格：只要不在描述里的字段、显式 `null`、超出范围的值，统统返回 400。文档也明确要求“不按其他模型推断参数”。

现有卡片的参数面板是手写的，按协议各有一套：`VIDEO_MODELS`、Seedream 的档位和像素表、可灵和 H3 在 APIMart 下的特例。同一个 Seedream 在网关上没有图层拆分，也没有自定义像素；可灵的时长范围、H3 的分辨率档位也和手写定义不同。

## 决策 (Decision)
- **Heighliner 服务商的图片、视频、3D 卡由能力描述生成参数面板**，不复用、也不映射其他协议手写的模型定义。常见的通用字段做成正式控件（比例、分辨率、时长、张数、音频、种子、负面提示词、输出格式）；`provider_options` 按 schema 自动生成控件，放在“高级”页；图片的 `size` 不显示。参考素材能接哪些角色、每个角色接几个，都由 `references` 决定。
- **能力描述跟绑定模型一起保存在服务商配置里**，在“获取模型列表”时写入或刷新，不在渲染时现查网关。描述过期导致的 400 原样显示在卡上，用户重新获取即可。
- **提交时只发描述里声明过、并且有值的字段**。卡片初始值取描述里的 `default`。切换模型时，不在新范围内的值重置为默认值，新模型没有的字段直接丢弃。
- 多个参数之间的组合规则（例如混元多视图必须有主图、首帧模式与参考模式互斥）不在本地重复校验，由网关返回 400 来表达。

## 考虑过的方案 (Considered Options)
- **复用手写模型定义，再映射到媒体协议字段**：现有面板可以直接用，但会把网关不接受的字段（图层拆分、MOV、自定义像素）带出去，引起 400。而且网关每上架或调整一个模型都要改代码，同一模型 ID 在不同协议下的差异还要靠特例来区分。
- **每次渲染卡片时现查网关目录**：描述永远是最新的，但离线时打不开参数面板，网关调整能力后面板也会悄悄变化。

## 结果与影响 (Consequences)
- **正面**：网关新上架的图片、视频、3D 模型，获取模型列表后就能用，不用改代码。
- **权衡**：同一个 Seedream 或 Seedance，在 Ark 原生协议下有专属功能，在 Heighliner 下没有，与 ADR 0004 “能力跟着协议走”一致。通用面板没有手写面板那样针对性的文案和提示。
- **已知限制**：组合规则只能在提交后通过网关的 400 发现。
