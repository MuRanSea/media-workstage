# ADR 0005: 生成结果独立成卡（生成卡 + 结果卡）

## 上下文 (Context)
生成结果原本写回发起生成的那张卡（`resultUrl` / `outputAssets`），再次点击是「重新生成」并覆盖上一次结果。这带来几个问题：一张卡同一时刻只能保存一个结果，无法对比和挑选；结果不能像素材那样被下游稳定引用（视频卡引用图片时只在连线瞬间快照 `resultUrl`，图片重新生成后引用的仍是旧图）；一次任务产出多个资产（图层拆分、连环组图）时只能靠手动「展开」按钮把资产变成卡片，且展开出的卡片与父卡没有连线。目标是让「生成」可以被频繁重复，每次产出都成为可复用的一等公民。

## 决策 (Decision)

### 1. 卡片分两种角色：生成卡与结果卡
- **生成卡**只保存提示词、模型和参数，可以无限次运行，自身不持有输出，按钮永远是「生成」，有任务在跑时显示「N 个生成中」。
- **结果卡**恰好持有一个产出（一张图、一段视频或一段文本），并带有生成时的只读参数快照。
- 角色由显式字段表示；卡片 `type` 仍是 `image | video | text`。角色不能由「有没有来源」推断：来源被删或将来的上传卡都没有来源。因此后端的封面与计数逻辑不必改动。

### 2. 结果卡在任务被后端接受后立刻出现
- 生成卡提交任务，拿到 `taskId` 后立刻在其右侧建一张占位结果卡，承载进度与失败状态。现有的 SSE 匹配（按 `taskId`）与 `applyTaskToCard` 只需把作用对象从生成卡换成结果卡，打开工程时对未终结任务的补齐逻辑也原样复用。
- 任务被接受之前的失败（参数校验、网络、服务商拒绝）只显示在生成卡上，不产生结果卡；任务被接受之后才失败的，留下一张带错误的结果卡。
- 文本生成是同步接口，没有占位阶段，返回后直接建结果卡；结果卡内容仍可手动编辑，图片与视频结果卡不可变。
- 一次任务产出多个资产时，一个资产一张结果卡：占位卡变成第一个资产的卡（按 `z_index` / 帧序，底图在前），其余依次新建并按网格排布。手动「展开图层 / 展开分镜」以及 `expansion.ts` 一并移除。

### 3. 连线：结果卡指向生成卡，下游固定引用某一张结果卡
- 结果卡上带一个指向生成卡的来源字段，沿用现有「连线是下游卡上的字段」（`promptSourceId`、`references`）的风格，不引入独立的 `edges[]`。
- **只有结果卡有输出端口**。视频卡引用的、图片/视频卡的提示词来源，都是某一张具体的结果卡，重新生成不会改变已连好的下游。视频结果卡暂时没有输出端口，因为目前没有下游能接收视频。
- 删除生成卡时，其结果卡保留并变成没有来源的独立卡。

### 4. 编号与布局
- `@图N` 只分配给图片结果卡（全局最大值 +1），生成卡不再有编号。
- 结果卡落在生成卡右侧一列，从生成卡顶部起向下找第一个不重叠的位置，绝不挪动已有卡片。

### 5. 旧工程在打开时一次性迁移
- 每张带结果的旧生成卡拆成「生成卡 + 结果卡 + 连线」。新卡的 id 由原卡 id 派生，重复打开结果一致，下次保存即落盘。
- 原图片卡的 `@图N` 编号让给迁移出来的结果卡，旧提示词里的 `@图3` 因此仍指向原图。
- 旧的 `references` 与 `promptSourceId` 重指向迁移出的结果卡，并弃用当年保存的 `url` 快照，改为直接读结果卡。
- 进行中的旧任务迁移为占位结果卡，沿用其 `taskId`。

### 6. 撤销
撤销只回退用户的手动编辑；快照恢复后，把快照之后由任务产生的结果卡并回来。用户主动删除结果卡仍可撤销，撤销后带着原来的 `taskId` 回来。

## 考虑过的方案 (Considered Options)
- **保持写回同卡，仅增加「历史结果」列表**：改动最小，但结果仍不能被下游稳定引用，多产出任务的「展开」问题依旧，且连线无法表达「这张图来自哪次生成」。
- **生成卡保留输出端口，含义是「永远用最新结果」**：改了想法重新跑，下游自动跟着新结果走；但结果不可复现，也与「结果卡就是一张素材」不一致。选择固定引用，代价是提示词助手重新生成后，要把下游的提示词线改接到新的文本结果卡。
- **独立的 `edges[]`**：得到统一的图模型，但要改 `project.json` 顶层结构、后端保存接口，以及复制、删除、撤销中所有连线相关逻辑，而目前只多出一种新关系。
- **任务成功后才建结果卡**：生成卡要同时挂多个 `taskId`，匹配与恢复逻辑都要重写，并发时也没有进度可显示。
- **旧工程双轨并存（不迁移）**：「卡片可能自带结果，也可能没有」会永久留在渲染和编译代码里。
- **新增卡片类型（如 `image_result`）表示结果卡**：需要同步修改后端封面与计数逻辑，收益只是让一个工程列表上的小数字更精确。

## 结果与影响 (Consequences)
- **正面**：每次生成都留下可复用、可对比的结果；下游引用稳定，顺带修掉了「图片重新生成后视频仍引用旧图」；多产出任务不再需要手动展开；将来的上传卡就是「没有来源的结果卡」，加入成本很低。
- **权衡**：图层拆分一次最多自动出 17 张卡，依赖网格排布和批量删除；提示词助手重新生成后，下游要改接新的文本结果卡；工程列表上的卡片计数会同时算入生成卡与结果卡。
- **已知限制**：后端没有取消任务的接口，删除仍在生成的占位卡只是删卡，任务照跑，产物仍会下载到工程文件夹；已迁移的工程用旧版本打开时会把结果卡当成普通卡片，无法回退。
